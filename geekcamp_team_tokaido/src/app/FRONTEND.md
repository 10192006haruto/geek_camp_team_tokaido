# ここメシ フロントエンド

> 2026-11-07更新（Yuuto、ふら担当分を巻き取り）：検索APIはクチコミ料理抽出の経路に接続済みです（`RESTAURANT_DATA_SOURCE`で`places`/`mock`を選択、[README](../../README.md#店舗データの取得元モック実api)）。途中結果（`uncheckedCount`）の表示を追加しました。

## 3条件の契約

検索範囲500m/1km/3km（初期1km）、今日の気分（任意・最大150 UTF-16コード単位）、営業中のみ（初期OFF）に統一しました。現在地はユーザー操作後に取得。ジャンル・予算入力はありません。

共有型はsrc/types/restaurants.tsを利用します。フロントのRestaurant.photosは表示用の任意拡張です。

```json
{
  "location": { "latitude": 35.6812, "longitude": 139.7671 },
  "radiusMeters": 1000,
  "mood": "麺が食べたい",
  "openNow": true
}
```

POST /api/restaurants/searchの結果をそのまま表示します。フロントは最大5件、必須のinferredMenu、必須の`uncheckedCount`（0以上の整数）を受理します。条件変更はAPIへ再送し、前回5件だけの並べ替えは行いません。実検索は同一条件でも再取得し、デモのみ候補を再利用します。気分は候補取得の検索語に使いません。

料理名・ジャンルから判定できる気分のみ優先。未対応の気分は距離順で、気分不一致でも除外しません。

## 途中結果（一部未確認）

Geminiの混雑・期限切れで一部の店舗のクチコミを確認できなかった場合、APIは確認できた店舗だけの結果と`uncheckedCount`（確認できなかった店舗数）を200で返します（[API契約](../../docs/api-contract.md#途中結果一部未確認)）。

- `uncheckedCount > 0`で結果があるとき：一覧の上に「混雑などのため、一部のお店（N件）のクチコミを確認できませんでした。確認できたお店の中から表示しています。」と「もう一度確認する」ボタンを表示（`role="status"`）。
- `uncheckedCount > 0`で0件のとき：「確認できたクチコミからは、条件に合う料理の情報が見つかりませんでした」と表示し、確認できなかった店を「料理がない」と断定しない。
- 「もう一度確認する」は同じ条件で検索し直す（実検索は毎回再取得、デモは同じ状態を再表示）。
- 結果見出しは、デモ／モック（`mock-`のID）／実データで切り替える。

## デモ

通常デモは料理名・引用・架空投稿者を持つフロント専用データで表示を確認します。検索API接続とは別で、実API・有料APIは呼びません。通常の現在地検索は、サーバーが`mock`なら東京駅周辺の架空店舗（離れた位置では0件）、`places`なら実店舗を返します。

「デモの表示状態」の0件・欠損・失敗・並べ替え失敗・一部未確認（混雑時）・遅延はフロント内の専用シナリオで、通常デモのHTTP結合確認とは別です。「一部未確認」は近い順に2件を確認できなかった扱いで除き、`uncheckedCount=2`として表示します。

## 状態・操作

位置情報拒否・タイムアウト・取得不能を区別。検索失敗時は前回結果・入力を保持します。AbortControllerと世代番号で古い応答を破棄。位置・気分をログや永続ストレージに保存しません。

詳細から戻る際のスクロール・カードフォーカス復元、ブラウザ履歴、ダイアログのフォーカス復帰、導入のスキップ・reduced-motion対応は維持しています。

## 検証

アプリルートでnpm run lint、npx tsc --noEmit、npm run buildを実行します。
フロントテストは既存scripts/test.mjs、サーバーはnode --test src/server/restaurants/*.test.mjs src/server/discovery/*.test.mjsで実行できます。
ブラウザ実機のフォーカス・位置許可・スクロール・reduced-motionはユニットテストと別に確認が必要です。

## 料理と根拠の表示

カードに料理名、詳細に原文引用・投稿者・元レビューへの安全なリンクを表示します。投稿日時、投稿者画像、翻訳の案内・原文はメタデータが提供された場合に表示します。地域性・現在の提供は断定しません。原文はHTMLとして挿入しません。

APIの504は時間切れ、503は利用不可として案内し、前回結果を保持します。取得側の帰属要件・モデル送信条件は実データ接続前に確認が必要です。
