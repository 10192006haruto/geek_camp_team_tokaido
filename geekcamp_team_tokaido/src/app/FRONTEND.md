# フロントエンドの作業メモ

今回の実装は`src/app/`内だけです。`_components/`に画面部品、`_lib/`に検索クライアント・フロント用の型・デモを配置しています。Next.jsの非公開フォルダなのでURLにはなりません。チームの共通型が導入されたら`_lib/restaurant-types.ts`をその型への参照に置き換えてください。

## 起動と確認

アプリルートで`npm run dev`を実行します。

- 「近くのご当地グルメを探す」は操作後に現在地を取得し、条件の確定後に`POST /api/restaurants/search`へ送信します。APIは今回実装していないため、未接続ならエラーの案内を表示します。
- 「位置情報を使わず、デモで試す」は東京駅付近の固定座標と架空店舗を使います。これはフロント内の画面プレビューであり、HTTPモックではありません。外部APIは呼びません。
- デモの絞り込みパネル内「開発用：画面の状態を確認」で、0件・null・エラー・遅延を再現できます。ジャンル・予算の選択肢と店舗情報は仮のデモ値です。
- 詳細はモーダル表示し、一覧をアンマウントせず、スクロール位置・条件を保持します。Escapeや一覧へ戻るボタンで閉じます。
- 導入はセッションにつき一度、約1.35秒。タップ・Enter・Space・Escapeでスキップできます。sessionStorageを使えない場合も操作できますが、再読み込み時の再演は防げません。

## 検証

アプリルートで`npm run lint`、`npx tsc --noEmit`、`npm run build`を実行します。
追加依存なしのロジックテストは、`src/app/`から以下を実行します。

```bash
../../node_modules/.bin/tsc --target ES2022 --module commonjs --esModuleInterop --skipLibCheck --outDir /tmp/kokomeshi-frontend-tests _lib/search.test.ts
node --test /tmp/kokomeshi-frontend-tests/search.test.js
```

実機では位置情報の許可・拒否・タイムアウト、キーボードでのパネル操作、フォーカス復帰、動きを減らす設定、モバイル幅を確認してください。

今回の確認結果：型チェックと9件のロジックテスト、本番ビルドに成功しました。`npm run lint`は既存の`eslint.config.mjs`が`eslint-config-next/core-web-vitals`を解決できず実行できませんでした。共通の依存関係・設定は変更していません。ブラウザ操作ツールが利用できなかったため、視覚確認と実ブラウザでの操作検証は未実施です。

## バックエンドとの接続時

- API契約に沿ったレスポンスを返す実装をYuuto担当の範囲に追加し、実際のHTTP疎通を確認します。今回のfetchテストは通信スタブを使用しています。
- 共通型を導入し、ジャンル・予算の許可値を合意してUIと同期します。
- 後藤担当の選定理由・ラベルをそのまま表示できる構造です。レビューの少なさだけで地域性を推測しません。
- 写真、出典、帰属表示、Google Maps URLの仕様と外部サービスの要件を確認します。
- APIから不明値をnullとして受け取り、0や営業していない状態とは区別します。
- ルートREADMEと既存設計資料は文書作成時点の記載を保持しています。このファイルが今回のフロント実装状況を補足します。
