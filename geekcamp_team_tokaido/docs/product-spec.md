# ここメシ 製品仕様

> 最新の担当分離：Nearby取得・検索APIへの接続はYuuto担当として今回の変更から外しました。ふら側は取得済み最大20候補を受け取るprepareReviewResultsと、最終5件の選定・表示までです。通常検索は旧モックのままです。[現在の担当境界と検証記録](review-search-integration-2026-11-07.md)を優先してください。

> ふら担当の料理抽出・画面表示の実装状況は[検証記録](review-dishes-implementation-2026-11-07.md)を参照してください。全体の新仕様は[レビュー料理抽出MVP仕様](review-dishes-mvp-spec.md)を参照してください。本書は既存のご当地判定・最大5件版の記録であり、レビュー抽出・最大20件版への実装時に更新します。

## 状態と目的

画面・検索API・ご当地判定を実装済みです。店舗取得は東京駅周辺の架空店舗を使うモックで、実店舗検索は未接続です。

旅行先や外出先で、現在地周辺の地域ならではの料理、穴場、地元で親しまれている店を発見します。主な利用端末はスマートフォン。おすすめ理由は取得情報に基づき、レビュー数の少なさから地域性や地元の支持を推測して断定しません。

## 確定したMVP体験

導入 → ホーム → 「近くのご当地グルメを探す」 → 現在地取得 → 絞り込み → 検索結果 → 店舗詳細。

### 導入とホーム

- クリーム色の背景、オレンジ系の位置ピン、中央にお茶碗。ピンが落下して一度だけ小さく弾み、下に「ここメシ」がふわっと現れ、ホームへ自然にフェードします。全体約1〜1.5秒。
- 軽量なCSS/SVGを優先し、不要なアニメーションライブラリを追加しません。演出中もホームの準備を進めます。
- タップ・キーボードでスキップ可能にし、同じタブのセッション中は繰り返しません。`prefers-reduced-motion`では落下・バウンドを抑えます。ストレージが使用不能でも操作を妨げません。
- ホームにブランド、短いコピー（例：「この街で出会う、ここならではの一皿。」）、主操作の検索ボタンと現在地を使う説明を置きます。未実装の認証・お気に入りボタンは出しません。

### 現在地と絞り込み

- 初期表示では位置情報を要求せず、検索開始操作後に取得します。駅名・エリアの手入力は対象外です。
- 拒否、タイムアウト、取得不能を区別し、非対応環境も案内します。拒否時はブラウザのサイト設定で位置情報許可を確認する説明を出し、変更後の再試行を用意します。アプリから許可ダイアログを強制再表示できる前提にしません。
- 自動追跡しません。明示的な再検索で位置を更新します。条件パネルを開閉するだけでは位置を再取得しません。
- 開発用固定座標を使う場合はユーザーが選べるモック操作として提供し、「モックモード／固定座標・架空店舗」と表示します。位置取得失敗を黙って固定座標に置き換えません。
- モバイルは下から開くパネルを基本とし、PCでも操作しやすくします。

| 条件 | 選択肢・初期値 |
| --- | --- |
| 半径 | 500m / 1km / 3km、初期値1km |
| 今日の気分 | 任意入力、最大150 UTF-16コード単位。初期値空欄＝おまかせ |
| 営業中のみ | ON/OFF、初期値OFF |

人数は含めません。現在地以外の条件は任意で、閉じる・結果から戻る操作でも選択を維持します。ジャンル・予算は検索条件から外します。

### 選定の確定ルール

- ご当地料理の提供根拠を必須にする。現在地の都道府県と料理の地域性を照合する。
- 半径内候補 → ご当地判定 → 営業条件 → 気分による並べ替え → 最大5件の順にサーバーで処理する。
- 気分は除外に使わない。料理名・ジャンルで判断できる指定のみ優先し、未対応・否定表現・空欄は距離順。同順位は距離順。
- 営業中のみONはtrueだけを採用し、false・nullを除外する。
- 条件変更はAPIへ再送し、前回の5件だけから再選定しない。
- 0件は「条件に合うご当地料理のお店を確認できませんでした」と案内。未確認と非提供を区別する。

### 結果と詳細

- 写真付きカードを中心に最大5件程度（API案では上限5件）。不足時に件数を水増ししません。
- 店名・料理ジャンル・距離・評価・レビュー数・おすすめ理由を表示します。写真なしは代替表示、未知は「不明」等で示し、0に変換しません。
- 距離は直線距離であると明記します。根拠なく徒歩時間に変換しません。
- 条件変更・再検索を可能にし、再検索成功まで直前の結果を保持します。検索中・失敗時には表示中の結果が前回のものと分かるようにし、適用済み条件と編集中の条件を分けます。
- 詳細に店名・写真・住所・評価・レビュー数・価格・営業情報・選定理由・Google Mapsでの経路導線を置きます。不明の営業情報を閉店扱いしません。経路先が不明なら導線を無効化または非表示にします。架空店舗へ実店舗の経路を捏造しません。
- 一覧に戻った際は条件・結果・スクロール位置を復元します。

### 状態とアクセシビリティ

| 状態 | 表示・操作 |
| --- | --- |
| 初期表示 | ホーム、位置情報の事前説明 |
| 位置取得中 | 進行表示、重複操作の防止 |
| 位置取得失敗 | 原因別説明、再試行、許可設定の案内 |
| 検索中 | 進行表示、前回結果との区別 |
| 成功 | 取得件数とカード一覧 |
| 0件 | 範囲を広げる・条件を変更する導線。3kmなら条件変更を案内 |
| APIエラー | 条件と前回結果を保持し、再試行 |
| 一部欠損 | 項目ごとの不明・代替表示。他の店舗は閲覧可能 |

ダイアログには名前を付け、開く際のフォーカス移動、フォーカスの囲い込み、Escapeで閉じる、起点へのフォーカス復帰を実装します。フォームラベル、キーボード操作、進行・エラーの読み上げ、文字のコントラストにも配慮します。

## 将来機能・対象外

お気に入り、認証、レビュー投稿、地図表示は将来機能です。実API連携は初期実装の必須条件ではなく、キー不要のモックから始めます。別バックエンドサーバー、有料API呼び出し、デプロイは今回行いません。

## 未確定事項

- Google Maps・Places Nearby Search・Geminiの利用可否、契約、費用、クォータ、必要フィールド、出典・写真帰属・保存条件。
- 将来表示する価格情報の取得根拠。価格帯から円の金額を推定しません。
- 穴場の定義、レビュー数の閾値、地域性・地元の支持を示す根拠。
- チェーン判定（2026-11-07決定）：全国展開している飲食チェーンを、店名リスト（`src/server/restaurants/national-chains.ts`、たたき台・後藤確認待ち）で除外する。地域チェーンは除外しない。Places APIにチェーンを示す項目はない。今後の展望として、同じ店名でText Searchした店舗数から自動判定する方法（費用・速度の確認が必要）を検討する。閾値と除外設定はバック側に置き、変更しやすくします。
- Geminiの必要性、入力情報、根拠確認、失敗時の扱い。生成文だけを事実の根拠にしません。
- 本番の位置情報の保持方針。MVPでは不要な永続化・ログ出力を避けます。

APIの詳細は[API契約](api-contract.md)、担当境界は[アーキテクチャ](architecture.md)を参照してください。
