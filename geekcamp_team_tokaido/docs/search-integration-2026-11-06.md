# 3条件検索とご当地判定の接続：実装記録

実施日：2026-11-06

## 今回の変更

検索条件を「検索範囲・今日の気分・営業中のみ」に統一し、画面から検索API、ご当地料理の判定、結果表示まで接続しました。店舗取得はモックです。実店舗APIの接続や有料API呼び出しは行っていません。

変更前はAPIが判定処理を呼ばずに最大5件を返し、フロントがその5件に営業条件・気分を適用していました。このため、6件目以降に条件に合う店があっても結果に入れられませんでした。変更後はサーバーで条件を適用してから、最後に最大5件に絞ります。

## 確定した検索条件

| 条件 | APIフィールド | 初期値・制約 |
| --- | --- | --- |
| 検索範囲 | radiusMeters | 500 / 1000 / 3000、初期値1000m |
| 今日の気分 | mood | 空文字＝おまかせ。最大150 UTF-16コード単位 |
| 営業中のみ | openNow | 初期値false。trueなら営業中と確認できる店のみ |

現在地は検索開始操作で取得します。条件変更だけでは位置を再取得しません。「現在地を更新して探し直す」では位置と検索結果を更新します。

ジャンル・予算は検索条件から外しました。店舗情報のcuisineLabel・priceLevelは表示用として残しています。

## APIと処理順序

`POST /api/restaurants/search` に次のJSONを送ります。

```json
{
  "location": { "latitude": 35.6812, "longitude": 139.7671 },
  "radiusMeters": 1000,
  "mood": "麺が食べたい",
  "openNow": true
}
```

全キー必須です。moodのnull、openNowの文字列、範囲外の座標・半径、旧条件cuisine・budgetMaxYen、未知のトップレベルキーは400で拒否します。気分は長さを検証してから前後の空白を除きます。

```text
画面から3条件と現在地を送信
 → 候補取得（現在は架空店舗）
 → 正規化・距離計算・半径内への絞り込み
 → classifyCandidatesでご当地料理の提供根拠を判定
 → 営業中のみの条件を適用
 → 距離順を基本に、気分に一致する候補を優先
 → 最後に最大5件へ制限
 → フロントは返却結果をそのまま表示
```

- ご当地料理の判定には既存の後藤担当の処理を使用し、結果を店舗IDで対応付けます。検索位置の都道府県を判定設定に渡します。
- 根拠がない候補は採用せず、件数を埋めるための追加もしません。
- 営業中のみONではisOpenNow=trueだけを採用し、false・nullは除外します。
- 気分は除外条件ではありません。料理の根拠にある料理名・店舗ジャンルで一致する店を優先し、同順位は距離順にします。
- 現在の気分判定は麺・和食・カフェ・郷土料理・焼肉の定型ルールです。空欄、未対応の表現（例：がっつり）、検出した否定表現は通常の距離順です。Geminiによる自由文理解ではありません。
- 生成されたおすすめ文は、気分の判定根拠に使いません。
- レスポンスは従来どおりrestaurants・returnedCountです。returnedCountは返却件数であり、検索した全候補の件数ではありません。

## フロントとの接続

通常検索と通常デモは、APIが選定済みの結果を返したことをserver-resultsとして扱い、フロントで再度フィルター・並べ替えをしません。

結果のメモリキャッシュキーに気分・営業条件も含めました。条件を変えた場合はAPIへ再送するため、前回の5件以外の候補も採用できます。同一条件のキャッシュ再利用は維持し、現在地更新は強制再取得します。

AbortController・世代番号による古い応答の破棄、検索失敗時の前回結果保持、詳細から戻る際の履歴・フォーカス・スクロール復元は維持しています。位置・気分を永続保存する処理は追加していません。

## モックとデモ

サーバーのモックを東京駅周辺の架空店舗9件に変更しました。営業していない店、営業不明、レビュー0件、評価不明、ご当地料理の根拠なし、当初の上位5件外のそば店を含めています。料理の提供根拠・地域性の出典も架空のテストデータです。

通常デモは東京駅の固定座標で同じHTTP APIを呼び、ご当地判定まで通ります。一方、0件・欠損・検索失敗・並べ替え失敗・遅延の表示状態デモは引き続きフロント内の専用データです。この表示状態デモはAPI結合検証とは別です。

現在地検索も現時点では同じモックを使います。東京駅から離れた位置では0件になるため、画面に架空店舗を使う旨を表示しました。

### 手動での確認手順

1. アプリルートでnpm run devを実行し、ホームを開く。
2. 「位置情報を使わず、デモで試す」を選択する。
3. 表示状態を通常にして、半径1km・気分空欄・営業中のみOFFで検索する。
4. 営業中のみONに変更し、営業中の候補で最大5件を返すことを確認する。
5. 気分を「麺が食べたい」に変更し、当初の上位5件外だった「【架空】深大寺そばの店 8」が先頭に入ることを確認する。
6. 詳細から戻る、条件を閉じる、表示状態デモで失敗させるなどの操作も確認する。

この手順はチーム向けの確認方法です。今回、実ブラウザでの操作確認は実施していません。
